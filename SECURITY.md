# Security policy

## Supported versions

This project is a static resume and portfolio template. We provide security updates for the current project state as it exists in the default branch.

Because this repository is intentionally lightweight and static, support is focused on the current release and the latest build of the default branch.

## Reporting a vulnerability

If you discover a security issue, please do not open a public GitHub issue.

Instead, report it privately through the repository's GitHub Security Advisories workflow if available, or use the maintainers' private contact channel for the project.

Please include:

- a concise description of the vulnerability
- affected files, components, or workflow steps
- the impact on the app or users
- reproduction steps if they are available
- any proposed mitigation or fix ideas

We ask for a reasonable amount of time to investigate and provide a fix before any public disclosure.

## Our response expectations

We aim to:

- acknowledge valid reports within a few business days
- assess the severity and impact quickly
- provide a fix or mitigation plan promptly when the issue is confirmed
- coordinate disclosure timing with the reporter when appropriate

## Safe harbor

We appreciate responsible disclosure and will not pursue action against researchers who report vulnerabilities in good faith and follow this process.

## Scope

This policy applies to security issues affecting the project itself, including:

- unsafe build or deployment behavior
- client-side code execution issues
- content injection or broken assumptions in the generated static output
- configuration mistakes that could expose content or break the deployment pipeline

This policy does not cover purely informational or non-security issues that are best handled through normal GitHub issues and contributions.
